# 棱版资源准入验证：独立成本证据与有界执行

本目录是一套**独立于生产代码的准入验证体系**，目标是回答：只按请求体大小判安全会放过昂贵成像，而按展开边数的静态上界粗暴拒绝又会误伤被裁域完全遮住的合法设计。所有结论来自真实 HTTP 路径与真实渲染测量，生产限额（8MiB 请求体、1.6 亿边遍历预算、512 画布、256 轮廓操作等）只被观察，**未被修改**。

## 组成

| 文件 | 角色 |
|---|---|
| `generate_cases.py` | 确定性生成 9 份曲线稿件（完整 `POST /v1/plates` 请求体），成对稿件字节差约 2%，展开复杂度相差约一个数量级 |
| `costprobe/main.go` | 独立探针：自带一份重写的展开/预算核算（不导入 `internal/validate` 的闸门），同时复用生产 `raster`/`vector` 做真实测量；可绕过闸门强制编译被拒稿件以取得其实际成本 |
| `run_admission.py` | 真实 HTTP 编排：构建未改动的生产二进制，在临时端口与临时数据根上跑建版、PUT 修订、封包导入、8MiB 体闸、异步取消、跨实例摘要核对 |
| `aggregate.py` | 把原始 JSON 汇总为 `aggregate.json` 与 `SUMMARY.md`（可复现矩阵与分类计数） |
| `run_all.sh` | 一键复现入口 |
| `cases/` | 生成的稿件与 manifest（可重新生成） |
| `evidence/` | 原始测量（`raw-*.json`）、汇总（`aggregate.json`、`SUMMARY.md`） |

## 复现

```sh
GO_BIN=/path/to/go bash tests/admission/run_all.sh
```

要求 Go 1.24+（模块声明版本；本次在 Go 1.24.4 linux/arm64 执行）与 Python 3 标准库。脚本不访问除 Go 构建外的网络，不占用固定端口，所有服务实例使用临时数据根并在结束时关停。单次完整运行约 1–2 分钟（含极端稿件约 9 秒的强制测量三次）。

## 方法：两条证据链如何独立

1. **静态上界（独立重算）**：探针自己实现 Q=16、C=24 的细分核算与 `segments × width × height × 4` 乘积，并把生产 1.6 亿常量复制为只读对照。探针同时调用真实 `validate.Compile` 记录生产判定；`force_segments_match_independent` 字段证明两份核算的边数逐案一致，没有估算分歧伪装成结论。
2. **实际测量（生产代码）**：探针的强制编译路径只做几何展开与逆变换，不经过预算闸门，因此被生产拒绝的稿件仍可在隔离进程内走真实 `raster.Render`/`vector.Export`，取得毫秒级耗时与 SHA-256 摘要。每案重复 3 次，报告 min/中位/max。

## 判定分类

- `accepted`：生产接受且渲染成功。
- `bounding-reject`：静态预算拒绝，且强制测量证实成像确实昂贵（如 c1 实测约 8.9 秒）。
- `conservative-reject`：静态预算拒绝，但强制测量显示渲染很便宜——稿件被画布外裁域完全遮住（a3 约 13ms、c2 约 120ms），属于上界不感知可见性造成的**保守误伤**。
- `estimate-defect`：独立核算与生产判定或强制编译边数不一致（本次矩阵中为 0 例）。
- `environment-timeout`：探针的有界 context 在完成前触发（见下），与准入拒绝是不同类别。

## 三类“失败”的区分

| 类别 | 观测方式 | 本矩阵证据 |
|---|---|---|
| 保守拒绝 | 生产 400 且错误为 `scene exceeds bounded rendering work`，但同稿强制渲染成功且耗时与被遮住程度相称 | a3、c2（静态乘积与未遮挡孪生几乎相同，实测便宜 29–74 倍） |
| 估算缺陷 | 探针独立边数与生产 `Compiled.Segments` 不符，或生产判定与独立乘积方向矛盾 | 9/9 逐案 `force_segments_match_independent=true`，无此类别 |
| 测试环境超时 | 探针以 2000ms 截止时间运行 c1，`context deadline exceeded` 在 2006ms 触发，SVG 同案仍成功 | `evidence/raw-probe-c1-timeout2s.json` |

生产 HTTP 成像路径自身带 30 秒截止时间；在当前限额下没有任何**被准入**稿件能跑到该阈值（最大准入案 c3 实测约 341ms），因此 504 只能在探针层以更紧的人为截止时间演示，这一区别在“未覆盖范围”中明确说明。

## 拒绝不留下部分稿本的核对方式

- 建版拒绝：比对拒绝前后 `state.json`，断言版面 id 不存在、artifact 计数不变；9 案全部通过。
- PUT 修订拒绝：对已存在版面追加超限稿本返回 400，断言稿本数仍为 1、原摘要不变、artifact 不增长。
- 封包导入拒绝：同上断言；另验证重名导入 409（不覆盖）、篡改摘要 400。
- 8MiB 体闸：8,389,633 字节请求返回 400，状态快照前后无差异。
- 跨实例：独立数据根的新实例导入封包后重渲染，PNG/SVG 摘要与首实例逐字节相同。

## 未覆盖范围（诚实声明）

1. **未提出也未验证新的准入算法**（如基于包围盒/裁域相交的可见性剪枝预算）。本任务只建立证据；任何放宽静态上界的改动都需要单独的设计与回归，且当前生产限额保持原样。
2. **生产 30s HTTP 截止时间的 504 路径未在真实服务上触发**：当前限额内无稿件可达；仅以探针 2s 人为截止验证取消机制本身有效。
3. 测量为单次机器（10 vCPU / 16GiB，Go 1.24.4 linux/arm64）的墙钟时间，毫秒值用于量级对比，不构成跨硬件 SLA；未做 CPU/内存剖析、GC 压力或并发争抢测量。
4. 矩阵只覆盖单形状单图层的曲线/直线轮廓与画布外矩形裁域；蒙版（mask）、多图层混合、多轮廓 evenodd、渐变笔刷的成本差异未做系统扫描（amber 示例的既有 walkthrough 仍覆盖这些功能的正确性）。
5. 未做故障注入（磁盘满、fsync 失败、断电）、容器/跨架构构建验证与压力测试；这些在 `docs/operations.md` 中本就标注为独立证据范畴。
6. 封包通道使用探针调用生产 `bundle.Seal` 生成信封，未覆盖手工构造的畸形信封全谱（已有 walkthrough 覆盖摘要篡改与尾随内容）。
7. 探针的强制编译路径是测试专用代码，刻意不携带生产闸门；它不能作为绕过生产准入的能力，因为生产 HTTP 与导入路径始终经过 `validate.Compile`，本矩阵已对同一批稿件验证这一点。
